# Group 22 Code of Conduct

## Purpose

This Code of Conduct defines how Group 22 will work together during the
SET09803 DevOps coursework.

The purpose is to ensure that all team members contribute fairly,
communicate professionally, and work together to deliver the project.

## Team Principles

All team members agree to:

- Treat all team members with respect and professionalism.
- Communicate clearly and respectfully in the team's agreed communication
  channels.
- Give every team member a fair opportunity to contribute.
- Share knowledge and help other team members when appropriate.
- Complete agreed tasks within the sprint where reasonably possible.
- Inform the team as early as possible if a task is delayed or a problem
  occurs.
- Raise technical or project issues rather than leaving them unresolved.
- Give constructive and respectful feedback during code reviews.
- Consider and respond to code review comments before merging work.
- Keep project work visible through GitHub Issues, branches, commits,
  Pull Requests and project boards.
- Follow the team's agreed Git workflow and branch policies.
- Do not work directly on the `master` branch.
- Do not merge work without the required peer review.
- Ensure that contributions to the project are genuine and accurately
  represented.
- Support the team's shared responsibility for development, testing,
  documentation and DevOps practices.

## Git and Pull Requests

Team members should:

- Create feature branches for development work.
- Use meaningful commit messages.
- Keep commits related to the work being performed.
- Create Pull Requests when work is ready for review.
- Allow another team member to review the Pull Request.
- Address reasonable review comments before merging.
- Follow the repository's branch protection and approval requirements.

## Code Review

Code reviews should be constructive and focused on improving the software.

Feedback should address the code, design, tests or documentation rather
than the individual.

The author should consider review comments and make agreed changes before
the Pull Request is merged.

## Communication and Meetings

Team members should:

- Attend agreed team meetings where reasonably possible.
- Participate in discussions about project decisions.
- Communicate in advance when they cannot attend a meeting or complete
  agreed work.
- Ensure that important decisions and project information are shared with
  the whole team.

## Contribution

Each team member is expected to make a meaningful contribution to the
project.

Contributions may include:

- Requirements and user stories
- Software development
- Unit and integration testing
- Code reviews
- Documentation
- DevOps configuration
- CI/CD
- Docker
- Project management and planning

Contributions should be visible through appropriate project activity such
as GitHub Issues, branches, commits, Pull Requests, reviews, testing and
documentation.

The team will maintain the required individual contribution spreadsheet
and agree contribution percentages at each assessment point.

## Resolving Disagreements

Where possible, disagreements should be discussed by the team and resolved
professionally.

The team should refer to the coursework requirements, agreed project goals
and technical evidence when making decisions.

If a disagreement cannot be resolved within the group, the appropriate
member of the module teaching team should be contacted.

## Academic Integrity

All work submitted by the team must comply with Edinburgh Napier
University's academic regulations and assessment requirements.

Team members must not misrepresent another member's work as their own or
falsify project activity or contribution.

## Breaches of the Code of Conduct

Concerns about a potential breach should first be raised with the team
where appropriate and supported by evidence.

Serious or unresolved concerns may be referred to the module teaching team
in accordance with the coursework procedures.

## Agreement

By participating in Group 22, team members agree to follow this Code of
Conduct and contribute to the project in a respectful, professional and
collaborative manner.
